# CubeCL server-sleep counterfactual

Declared before candidate execution. Diagnostic only, not a production sleep-policy change.

- Tenferro: 40e24634 plus the validated read-path repair, identified by ../read-path-results/candidate.patch. Benchmark source: 9a5b104 benchmark_gpu_rust. Both binaries use the same local CubeCL-common override from CubeCL 5939d8e3b1c479ed6db31de5f01cb6d432178f2d. Build baseline first, save binary, then change ONLY SLEEP_STEP_SERVER from 150 microseconds to zero. Client sleep, spin/yield budgets, synchronization, resource ownership, kernels and timing code unchanged. Archive sources, lockfiles, patch and hashes.
- Need: previous large-BMM profiles show ~173 us eager pointer resolution / ~113 us trace flush and ~200 us device-service sleeps overlapping inter-kernel idle gaps; GPU GEMM itself matches Torch at ~2.064 ms. Isolate server sleeping before choosing a production repair.
- Platform: existing CUDA container bench-gpu-20260919, A100 80GB PCIe, release, cargo -j16. CPU/provider threads explicitly 1 using scripts/thread_env.sh; no affinity. CubeCL service threads remain separate and are NOT part of the provider's 1T count. The no-sleep diagnostic can consume CPU continuously; record process user/system CPU and elapsed time, do not promote it as a production solution.
- Cases: f64 batched matmul with batch=1,32,1024 and m=n=k=256, plus elementwise_chain_f64_1k and elementwise_chain_f64_1m. Eager and trace, 5 warmups/30 samples. Inputs/setup outside timing, outputs retained until synchronization and timer stop; validation/download afterward. Small cases are public-API latency diagnostics, not shared-session throughput.
- Three fresh-process baseline/candidate pairs per backend, all cases per process. Baseline first in rounds 1/3, candidate first in round 2. Sequential, no compilation/testing concurrently. Retain medians/IQR and all records. Primary gate: candidate/baseline median <=0.97 for large BMM, each backend and every round. Nonregression diagnostic: <=1.10 on all remaining cases in every round. Every numerical verification must pass. No selective reruns/exclusions.
- Validity: no other GPU compute process, idle GPU utilization <=5%, host 1-minute load/available CPU <=0.5 before collection; log host load/processes and GPU state. Record CPU usage per process. Failed gates make the whole experiment inconclusive, not partially successful.
- Collect separate CUDA+OSRT profiles for baseline/candidate large BMM eager/trace using the focused suite. Check steady-state GEMM names/durations and DSD worker sleeps/gaps. Do not use profiled times as performance results.
- Outcome: determine whether eliminating server sleep closes the gap; retain remaining client/service/dispatch overhead. Production solution must avoid continuous idle CPU use and requires a separate focused design/test of wakeup semantics.
